# Deep Search Embabel Backend - Design Document

## 1. Overview

A Spring Boot application leveraging the **Embabel Agent Framework** to provide intelligent, goal-driven deep search capabilities. The application uses the existing `tavily-search-client` library as a tool for executing web searches within agentic workflows.

**Module name:** `deep-research-embabel-backend`

**Tech stack:**
- Kotlin 2.3.20, JVM 25
- Spring Boot 3.5.12
- Embabel Agent Framework 0.3.4-SNAPSHOT
- Tavily Search Client (internal module)
- Ollama (gemma3:4b for simple tasks, gemma3:12b for complex reasoning)

## 2. Goals

### 2.1 Primary Goals
- Provide a REST API for deep search queries that go beyond simple keyword matching
- Use Embabel's dynamic planning to orchestrate multi-step search workflows
- Leverage Tavily Search API for high-quality web search results
- Support iterative refinement of search results through agentic reasoning

### 2.2 Non-Goals (Phase 1)
- UI/frontend (backend only)
- Persistent storage of search history
- Multi-tenancy

## 4. Domain Model

### 4.1 Core Domain Objects

```kotlin
/**
 * User's search request with optional refinement parameters.
 */
data class SearchRequest(
    val query: String,
    val maxDepth: Int = 3,              // Maximum refinement iterations
    val includeSources: Boolean = true,  // Include source URLs in response
    val topic: String? = null           // Optional topic filter
)

/**
 * Aggregated result from deep search.
 */
data class DeepSearchResult(
    val query: String,
    val summary: String,                // LLM-synthesized answer
    val sources: List<SourceReference>, // Supporting sources
    val iterations: Int,                // Number of refinement cycles
    val confidence: Double              // Confidence score (0.0-1.0)
)

data class SourceReference(
    val title: String,
    val url: String,
    val relevance: Double
)

/**
 * Represents a refined/expanded search query generated by the agent.
 */
data class RefinedQuery(
    val originalQuery: String,
    val refinedQuery: String,
    val rationale: String               // Why this refinement was chosen
)

/**
 * Search context maintained on the Embabel blackboard.
 */
data class SearchContext(
    val request: SearchRequest,
    val queries: List<RefinedQuery> = emptyList(),
    val rawResults: List<TavilySearchResult> = emptyList(),
    val synthesizedSummary: String? = null
)
```

## 5. Agent Design

### 5.1 DeepSearchAgent

The core agent using Embabel's annotation-based model:

```kotlin
@Agent(description = "Performs deep, multi-iteration web search with query refinement and result synthesis")
class DeepSearchAgent(
    private val tavilyClient: TavilyClient,    // Injected from tavily-search-client
    private val tavilyClientConfig: TavilyClientConfig
) {

    @Action
    fun initializeContext(request: SearchRequest, context: OperationContext): SearchContext {
        return SearchContext(request = request)
    }

    @Action
    fun executeSearch(searchContext: SearchContext, context: OperationContext): SearchContext {
        val query = searchContext.queries.lastOrNull()?.refinedQuery 
            ?: searchContext.request.query
        
        val tavilyQuery = SearchQuery(
            query = query,
            searchDepth = SearchDepth.ADVANCED,
            maxResults = 10,
            includeAnswer = true
        )
        val result = tavilyClient.search(tavilyQuery)
        return searchContext.copy(
            rawResults = searchContext.rawResults + result
        )
    }

    @Action
    fun refineQuery(searchContext: SearchContext, context: OperationContext): RefinedQuery {
        val prompt = buildRefinementPrompt(searchContext)
        return context.ai()
            .withLlm("ollama/gemma3:12b")
            .createObject(prompt, RefinedQuery::class)
    }

    @Action
    fun synthesizeResults(
        searchContext: SearchContext,
        context: OperationContext
    ): DeepSearchResult {
        val prompt = buildSynthesisPrompt(searchContext)
        return context.ai()
            .withLlm("ollama/gemma3:12b")
            .createObject(prompt, DeepSearchResult::class)
    }

    @AchievesGoal(description = "Complete deep search with synthesized answer and sources")
    @Action
    fun completeSearch(searchContext: SearchContext): DeepSearchResult {
        // Terminal action - returns final result
        return searchContext.synthesizedSummary?.let { summary ->
            DeepSearchResult(
                query = searchContext.request.query,
                summary = summary,
                sources = searchContext.rawResults.flatMap { r ->
                    r.results.map { SourceReference(it.title, it.url, it.score) }
                },
                iterations = searchContext.queries.size,
                confidence = 0.85
            )
        } ?: DeepSearchResult(
            query = searchContext.request.query,
            summary = "No results found.",
            sources = emptyList(),
            iterations = 0,
            confidence = 0.0
        )
    }
}
```

### 5.2 Execution Flow (Inferred by Embabel Planner)

```
SearchRequest 
  → initializeContext() → SearchContext
  → executeSearch() → SearchContext (with rawResults)
  → refineQuery() → RefinedQuery
  → executeSearch() → SearchContext (with more results)
  → [replan loop until maxDepth or completeness condition met]
  → synthesizeResults() → DeepSearchResult
  → completeSearch() → DeepSearchResult [ACHIEVES GOAL]
```

### 7.3 LLM Model Strategy

| Model | Purpose | Usage |
|-------|---------|-------|
| `gemma3:4b` | Simple tasks: context initialization, basic parsing, formatting | Default LLM, lightweight operations |
| `gemma3:12b` | Complex reasoning: query refinement, result synthesis, evaluation | `refineQuery()`, `synthesizeResults()` |

Model selection in code uses `context.ai().withLlm("ollama/gemma3:12b")` for complex tasks and `context.ai().withDefaultLlm()` (resolves to `gemma3:4b`) for simple ones.

## 8. Open Questions / Decisions Needed

1. **Ollama Model Availability**: Ensure `gemma3:4b` and `gemma3:12b` are pulled locally (`ollama pull gemma3:4b`, `ollama pull gemma3:12b`)
2. **Resource Constraints**: gemma3:12b requires ~8GB VRAM; verify target deployment environment has sufficient GPU/memory
3. **Search Depth Strategy**: Should the agent dynamically choose Tavily search depth (BASIC/ADVANCED) or always use ADVANCED for deep search?
4. **Result Caching**: Should we cache Tavily results to avoid redundant API calls during refinement?
5. **Streaming**: Should the API support SSE streaming for real-time progress updates?
6. **MCP Exposure**: Should agents be exposed as MCP tools for external consumption?
7. **Authentication**: Any API auth requirements for the REST endpoints?
8. **Fallback Strategy**: What happens if Ollama is unavailable — graceful degradation or hard fail?
